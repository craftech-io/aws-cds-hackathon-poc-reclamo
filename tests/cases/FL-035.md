# FL-035 · Aprobación rechazada

| Campo | Valor |
|---|---|
| Área | E · Cargos y débitos |
| Actores | operador |
| Canal | consola |
| Disparador | la operadora rechaza con motivo ("el cargo corresponde a un pedido del 02/09") |
| Reglas | `SM` |
| Depende del modelo | Sí (ver Oráculo) |
| Fuente | `docs/flows-catalog.md` FL-035; `docs/test-plan.md` §2.2, §4.3 y §4.5 |

## Entrada

- Mundo `qa-<runId>-sc05`, reloj `PAUSED`.
- Clon de `C23` con una aprobación `PENDING` pedida por el agente (mismo camino que `FL-034` hasta `AWAITING_APPROVAL`).
- Principal `OPERATOR`; motivo: "el cargo corresponde a un pedido del 02/09".

## Pasos

1. Precondición: `Approval` `PENDING` y reclamo `AWAITING_APPROVAL`.
2. `console.approvals.decide(REJECTED, reason)` como `OPERATOR`.
3. El reclamo pasa a `HUMAN_REVIEW`; la operadora responde por escrito con el fundamento (`FL-089`).
4. `conv.settleProbe`; `snapshot`.

## Resultado esperado

- **R1** · `Approval.decision = REJECTED` con `reason` guardado y `AuditLog ACTION REJECTED` con el `staffId`. _Dónde:_ `snapshot.complaints[].approvals`, `snapshot.audit`.
- **R2** · `Complaint.status = HUMAN_REVIEW`. _Dónde:_ `snapshot.complaints[]`.
- **R3** · La respuesta escrita del operador lleva el fundamento (lo asierta `UI`). _Dónde:_ `approvals.spec.ts`.

Negativos (se asiertan después de la quiescencia, `CONVENCIONES.md`):

- **N1** · Ninguna reversión ni claim `REV#`.
- **N2** · Ningún `APPROVAL_DECIDED` ejecutable encolado para esa aprobación.

## Oráculo

La decisión y sus efectos son código; la precondición (aprobación `PENDING` pedida por el agente) es la de `FL-034` (fila `SC-05/3` de §4.3: `ABOVE_CAP` → `request_operator_approval` → `AWAITING_APPROVAL`). Alternativas aceptadas: ninguna. `SC-05/5` no tiene fila propia en §4.3 (pedido al architect).
