# FL-123 · Salir

| Campo | Valor |
|---|---|
| Área | O · Superficies públicas, alta propia e invitados |
| Actores | invitado, personal |
| Canal | consola |
| Disparador | "Salir" |
| Reglas | `docs/landing-spec.md` §9.7 |
| Depende del modelo | No |
| Fuente | `docs/flows-catalog.md` FL-123; `docs/architecture-guests.md` §4; `docs/landing-spec.md` §9.7; `docs/test-plan.md` §2.2 y §4.5 |

## Entrada

- `UI`: una sesión de invitado de alta propia y una del personal, con refresh token, en el `ui-server`.
- `SR`: la sesión de `su2` abierta por Playwright en `SC-24/7`.

## Pasos

1. Tocar "Salir" en el shell de la consola.
2. Leer `sessionStorage` y la URL.
3. Pedir tokens nuevos con el refresh token revocado.
4. (`SR`) `SC-24/12`.

## Resultado esperado

- **R1** · Se llama `RevokeToken` con el refresh token y se limpia `sessionStorage`. _Dónde:_ `routers/guest.test.ts`, `guest-session.spec.ts`.
- **R2** · La web vuelve a `/` (no a `/login`) y la landing se ve como la de un visitante público (CTA "Probar Reclamo en regla" e "Ingresar"). _Dónde:_ `guest-session.spec.ts`.
- **R3** · El refresh token revocado no emite tokens. _Dónde:_ `guest-session.spec.ts`, reporte de `SC-24/12`.

Negativos:

- **N1** · Ningún token queda en `sessionStorage`, `localStorage` ni en la evidencia.

## Oráculo

No depende del modelo.

## Pruebas que lo cubren

- **U (unitario)** · `routers/guest.test.ts` — asierta la revocación del refresh token al salir.
- **UI (Playwright local)** · `guest-session.spec.ts` — asierta "Salir" → `/`, `sessionStorage` vacío y el refresh revocado.
- **SR (escenario en `poc`)** · `SC-24/12`
  - `SC-24/12` (`docs/test-plan.md` §4.5): Playwright "Salir" → `/`; el refresh token revocado no emite tokens

## Evidencia que se guarda

- Salida de vitest de `[FL-123]`; captura de `guest-session.spec.ts` en `/` después de salir.
- `scenario-report.json`: el error del intento de refresh de `SC-24/12` (sin tokens).
