# FL-009 · Consulta que requiere gestión: registrada con número

| Campo | Valor |
|---|---|
| Área | B · Consulta, reclamo y registro |
| Actores | cliente, agente |
| Canal | WhatsApp |
| Disparador | "necesito el detalle de todos los pagos del año para una presentación" |
| Reglas | registro de consultas que requieren análisis (BCRA 3.1.3) |
| Depende del modelo | Sí (ver Oráculo) |
| Fuente | `docs/flows-catalog.md` FL-009; `docs/test-plan.md` §2.2, §4.3 y §4.5 |

## Entrada

- Mundo `qa-<runId>-sc11`, reloj `PAUSED` en el inicio del escenario.
- Persona clon de `C08`, identificable por el autopiloto.
- Mensaje: "necesito el detalle de todos los pagos del año para una presentación".

## Pasos

1. `wa.inbound`; el clasificador no registra (consulta) y encola el turno.
2. El agente llama `register_complaint(kind CONSULTA, type INFORMATION_REQUEST)` antes de investigar.
3. El código manda el `COMPLAINT_ACK` con el número por la compuerta.
4. `conv.settleProbe` hasta `settled`; `snapshot`.

## Resultado esperado

- **R1** · `Complaint.kind = CONSULTA`, `type = INFORMATION_REQUEST`, con `complaintNumber` correlativo del mundo. _Dónde:_ `snapshot.complaints[]`.
- **R2** · Una entrada `FILED` en el registro con el mismo número y `seq` consecutivo. _Dónde:_ `snapshot.register`.
- **R3** · Tres timers `SCHEDULED` (`OPERATOR_REMINDER`, `SUPERVISOR_ESCALATION`, `DEADLINE`) según `services/business-days.ts`. _Dónde:_ `snapshot.timers`.
- **R4** · `COMPLAINT_ACK` con texto fijo del código (número, tipo, plazo), `ALLOWED` en la cinta. _Dónde:_ `snapshot.tape`.

Negativos (se asiertan después de la quiescencia, `CONVENCIONES.md`):

- **N1** · Ninguna tool de investigación ni acción aparece en `TURN#` antes de `register_complaint`.

## Oráculo

Fila `SC-11/6`, `SC-11/7` de §4.3. Hechos exigidos: `register_complaint` con `INFORMATION_REQUEST` antes de toda tool de investigación. Alternativas aceptadas: ninguna.
