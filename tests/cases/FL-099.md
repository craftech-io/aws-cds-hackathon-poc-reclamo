# FL-099 · Aislamiento entre mundos

| Campo | Valor |
|---|---|
| Área | M · Consola, cumplimiento y métricas |
| Actores | invitados, personal |
| Canal | consola |
| Disparador | un id de otro mundo en un procedimiento; dos mundos de invitado con la misma persona y los mismos timers de plantilla, los dos en `RUNNING` |
| Reglas | `worldProcedure` |
| Depende del modelo | Sí (ver Oráculo) |
| Fuente | `docs/flows-catalog.md` FL-099; `docs/test-plan.md` §2.2, §4.3 y §4.5 |

## Entrada

- Mundos `qa-<runId>-sc18`, `qa-<runId>-sc22a` y `qa-<runId>-sc22b` (plantilla `guest`, la misma persona `C01`), y `gprobe` (solo lectura).
- Un id de otro mundo (de `demo`) para un procedimiento de consola.
- Una preferencia centinela por mundo para la memoria (`SC-22/6`).

## Pasos

1. (`SC-18/6`, `SC-22/2`) Un procedimiento con un id de otro mundo → 403.
2. (`SC-22/3`) Sesión B en el mismo mundo que A → aviso "otra sesión usó este mundo" sin botón de reinicio; una re-emisión de A no lo dispara.
3. (`SC-22/6`) `sc22a` y `sc22b` en `RUNNING`: un mensaje y un centinela en cada uno; reiniciar `sc22a`.
4. (`SC-18/10`) `fence.probe({kind: WORLD_PATHS})` contra `gprobe` con el hash antes y después.

## Resultado esperado

- **R1** · El id de otro mundo responde 403 con `AuditLog DENY CROSS_WORLD`. _Dónde:_ reporte, `snapshot.audit`.
- **R2** · El aviso de otra sesión aparece para B y no para la re-emisión de A. _Dónde:_ Playwright (`SC-22/3`), `isolation.spec.ts`.
- **R3** · Nombres de schedule distintos entre `sc22a` y `sc22b` (`tm-<worldId>-e<epoch>-…`); al reiniciar `sc22a`, la memoria (actores `w-<worldId>-…`) y los schedules de `sc22b` siguen intactos. _Dónde:_ `snapshot.schedules`, `memory.inspect`.
- **R4** · `fence.probe`: (a) sobre firmado con `QaSimEnvelopeKey` → `SIM_KEY_WORLD_MISMATCH`, sin reclamo, acuse ni evento; (b) disparo con la versión vigente → `EARLY_FIRE_DISCARDED CLOCK_PAUSED`; (c) mocks por Function URL → 403 `CALLER_WORLD_DENIED` e invocación directa → `AccessDenied`; (d) purga y reinicio sin ticket → `PURGE_REQUEST_MISSING` y `RESET_REQUEST_MISSING`. _Dónde:_ salida de `fence.probe`.
- **R5** · El hash de `gprobe` es igual antes y después, y sigue `READY`. _Dónde:_ salida de `fence.probe`.

Negativos (se asiertan después de la quiescencia, `CONVENCIONES.md`):

- **N1** · Ningún dato de otro mundo en ninguna respuesta.

## Oráculo

La memoria de `SC-22/6` la produce la extracción de Memory (un modelo): el paso espera a que aparezca cada centinela (tope 600 s) antes de reiniciar. El resto (403, aviso, schedules, cercas de `fence.probe`) es código e IAM, sin alternativas.
