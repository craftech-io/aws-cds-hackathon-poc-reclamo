# FL-115 · Código incorrecto o vencido

| Campo | Valor |
|---|---|
| Área | O · Superficies públicas, alta propia e invitados |
| Actores | visitante |
| Canal | web |
| Disparador | un código que no coincide o de más de 24 h |
| Reglas | ADR-0020 |
| Depende del modelo | No |
| Fuente | `docs/flows-catalog.md` FL-115; `docs/architecture-guests.md` §4 y §16; `docs/landing-spec.md` §9.3; `docs/test-plan.md` §2.2 y §4.5 |

## Entrada

- Un alta en `CODE_SENT` (FL-112) con email `success+qa-<test>-<n>@simulator.amazonses.com`.
- `UI`: el Cognito falso con el reloj real inyectado para vencer el código a las 24 h; un código errado (distinto de `lastCode(email)`).
- `U`: un `signupId` reemplazado (`SUPERSEDED`), uno vencido (más de 48 h) y uno ausente de `sessionStorage`.
- `SR`: el alta `su1` de `SC-24` con un código inventado.

## Pasos

1. (`UI`) En `/signup/verify`, escribir un código errado y tocar "Confirmar".
2. Avanzar el reloj real inyectado más de 24 h y confirmar con el código que se había enviado.
3. Borrar el `signupId` de `sessionStorage` (o reemplazar el pedido con otro `signup.start`) y confirmar.
4. (`SR`) `SC-24/3`: `guest.confirm` con un código inventado.

## Resultado esperado

- **R1** · Código errado → `CODE_MISMATCH` (de `CodeMismatchException` de Cognito) y el copy "Ese código no es correcto. Probá de nuevo." / "That code isn't right. Try again."; la pantalla deja reintentar y pedir otro. _Dónde:_ `routers/signup.test.ts`, `signup.spec.ts`.
- **R2** · Código de más de 24 h → `CODE_EXPIRED` (de `ExpiredCodeException`) y el copy "Este código venció. Pedí uno nuevo." / "This code expired. Request a new one.". _Dónde:_ `routers/signup.test.ts`, `signup.spec.ts`.
- **R3** · `signupId` reemplazado, vencido o ausente → `SIGNUP_RESTART` **sin llamar a Cognito**; la web vuelve a `/signup` con "Empezá de nuevo el alta: tu código anterior ya no vale." / "Start the sign-up again: your previous code no longer works.". _Dónde:_ `routers/signup.test.ts`, `signup.spec.ts`.
- **R4** · En todos los casos el usuario sigue `UNCONFIRMED`; ningún lead, mundo ni ticket. _Dónde:_ `routers/signup.test.ts`.
- **R5** · (`SC-24/3`) `guest.confirm` con un código inventado → `CODE_MISMATCH`. _Dónde:_ reporte de `SC-24/3`.

Negativos:

- **N1** · Ningún `ConfirmSignUp` en el caso de R3.
- **N2** · Ningún código ni email en logs ni en la evidencia.

## Oráculo

No depende del modelo: el código lo valida Cognito y el pedido lo valida el BFF.

## Pruebas que lo cubren

- **U (unitario)** · `routers/signup.test.ts` — asierta el mapeo de `CodeMismatchException` y `ExpiredCodeException` y `SIGNUP_RESTART` sin llamar a Cognito.
- **UI (Playwright local)** · `signup.spec.ts` — asierta el copy exacto de §9.3 para errado y vencido y la vuelta a `/signup` con `SIGNUP_RESTART`.
- **SR (escenario en `poc`)** · `SC-24/3`
  - `SC-24/3` (`docs/test-plan.md` §4.5): `guest.confirm` con un código inventado → `CODE_MISMATCH`; `guest.resend` ×4 en la hora → el cuarto `RATE_LIMITED`

## Evidencia que se guarda

- Salida de vitest de `[FL-115]`; capturas de `signup.spec.ts` de los tres mensajes.
- `scenario-report.json`: respuesta de `guest.confirm` con el código inventado.
